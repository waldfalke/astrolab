# Мунданные астрологические часы

Это прогноз местных суток для выбранного города без натальной карты человека и
без карты основания города. Он соединяет общий небесный фон с местной геометрией:
движением ASC и MC, домами, точными контактами и фазовыми состояниями.

На входе нужны дата, координаты и постоянное UTC-смещение на протяжении этих
суток. Название города используется в отчёте, но не заменяет координаты. Если в
эту дату часы переводились, фиксированное смещение не описывает сутки корректно.

## Подготовка

Из чистой копии репозитория:

```powershell
uv sync --frozen --group engine-a
pwsh infra/ephe/get-ephe.ps1 -Source web
$env:SWISS_ENGINE = "a"
$env:SWISS_EPHE_PATH = (Resolve-Path "infra/ephe/files").Path
$env:REQUIRE_ENGINE_A = "1"
```

Собери день в новый каталог:

```powershell
uv run python artifacts/mcp-recipes/build_day_ribbon.py `
  --date 2026-10-10 `
  --lat 45.04 `
  --lon 38.98 `
  --tz 3 `
  --aspect-orb 6 `
  --output city-day-run
```

Команда использует локальный Engine A и действующий MCP `natal` через in-process
transport; отдельный сервер и Docker не нужны. Каталог назначения не должен
существовать до запуска.

## Что получится

В `city-day-run/ribbon/` находятся:

- `states.json` — состояние неба и местных домов для каждой минуты, 1441 кадр;
- `events.json` и `events.csv` — рассчитанные события только выбранных суток;
- `boundary-context.json` — полные интервалы первого и последнего восходящего
  состояния, если их начало или конец лежат за гражданской полуночью;
- `author-manifest.json` — метод, параметры, полнота, происхождение и хеши.

Краевой контекст не расширяет день. Внешний переход помогает понять состояние,
которое уже идёт в 00:00 или ещё продолжается после 24:00, но не становится
событием отчётной даты.

Лента содержит ингрессии ASC, его аспекты к планетам, соединения планет с MC,
переходы планет через движущиеся куспиды и межпланетные аспекты, найденные между
соседними минутными состояниями. Точное время — линейная оценка внутри сохранённой
минутной скобки, а не обещание события.

## Поручение автору

Передай агенту каталог `ribbon/` и два файла:

- `artifacts/report-templates/city-day-astrology.md` — рабочее основание;
- `artifacts/report-templates/city-day-reading.html` — читательский HTML.

```text
Составь мунданный прогноз дня для названного города без натальной карты.
Сначала заполни city-day-astrology.md, затем сверь с ним итоговый HTML.
Хронологию и события бери только из events.json и events.csv.
boundary-context.json используй только для понимания первого и последнего
восходящего состояния. Внешние переходы не называй событиями отчётного дня.
Найди связи, задающие целое суток, и только потом выбери важные эпизоды.
Не превращай точный контакт в интервал без рассчитанных границ.
Не считай две записи одной геометрии двумя независимыми основаниями.
Достоинство показывает доступность способа действия, фаза — состояние в цикле,
аспект — отношение участников; одно не подменяет другое.
Пиши о качестве времени и возможных способах действия, а не о событиях,
которые якобы обязательно произойдут со всеми жителями города.
Планеты и аспекты не являются действующими лицами текста.
Укажи фактическую модель и effort в скрытых полях обоих шаблонов.
Не оставляй токены шаблона, битые ссылки или внешние ресурсы.
```

Число важных эпизодов следует из рассчитанного материала. Формат не требует
одинакового числа часов, акцентов или абзацев для разных дат. `states.json`
нужен для проверки контекста события, а не для пересказа каждой минуты.

## Граница результата

Расчёт воспроизводит заявленную геометрию и происхождение данных. Авторское
толкование остаётся астрологической интерпретацией, а не установленным прогнозом
событий. Формат не делает личных выводов и не использует сведения о человеке.
